Guidance for Claude when it works in this repository.

## Project overview

This repository holds the marketing site for Bridgit Social, a location-based
networking app. The site is a static, multi-page HTML site. The site is not a
single-page app and does not use a JavaScript framework.

Production URL: https://bridgitsocial.com (custom domain, set in `CNAME`).

## Tech stack

- Plain HTML pages, one file per page (no templating engine for pages)
- Plain CSS, hand-maintained directly in `assets/css/main.css` and
  `assets/css/noscript.css`. There is no Sass build step: `vite.config.js`
  does not compile Sass, and the `sass` package is not installed. An old,
  unused Sass source tree is archived at `archive/legacy-sass/` — see the
  README there before touching it.
- jQuery plus small helper scripts for animation and layout (`assets/js/`)
- Vite as the build and dev-server tool
- Blog posts written in Markdown, converted to HTML by a custom Node script
  (`scripts/build-blog.js`, using `marked` and `gray-matter`)

## Folder structure

- `index.html` — main landing page (hero, features, screenshots, contact form)
- `waitListPage.html` — waitlist signup page
- `instructions.html` — "how to use the app" page
- `support/support.html` — support page
- `blog/index.html` — blog index page
- `blog/posts/*.md` — blog post source files (edit these, not the generated HTML)
- `blog/posts/*.html` — generated blog post pages (build output, checked into git)
- `PrivacyPolicy/` — privacy policy and terms of use pages
- `email-templates/` — `welcome.html` and `whatsNext.html` email templates
- `assets/css/` — the real source of the site's styles (`main.css`,
  `noscript.css`), hand-edited directly, plus small CSS-only assets (icons,
  overlays). No compile step — edit these files themselves.
- `assets/js/` — jQuery and supporting JS libraries plus `main.js`
- `assets/webfonts/` — Font Awesome font files
- `images/` — site images, sorted into `backgrounds/`, `banners/`, `email/`, `fulls/`,
  `icons/`, `screenshots/`
- `scripts/` — `build-blog.js` (blog build) and `deploy.sh` (GitHub Pages deploy)
- `archive/legacy-sass/` — old, unused Sass source. Not wired into the build
  and not kept in sync with `assets/css/`. Reference only; see its README.
- `dist/` — build output. Generated by Vite and the blog build script. Do not hand-edit.
- `node_modules/` — installed dependencies. Do not edit.

## Common commands

```
npm run dev            # start the Vite dev server
npm run build           # production build with Vite
npm run build:blog     # convert blog/posts/*.md to HTML + RSS feed
npm run preview         # preview a production build locally
npm run deploy           # build + build:blog + push dist/ to the gh-pages branch
npm run format           # run Prettier and write changes
npm run format:check    # run Prettier in check-only mode
```

## Code style

- Prettier config (`.prettierrc`): double quotes, semicolons on, 2-space indent,
  100-character print width, trailing commas where valid in ES5, LF line endings.
- EditorConfig (`.editorconfig`): UTF-8, LF line endings, 2-space indent for
  `.js`, `.json`, `.html`, `.css`, `.md`. Trim trailing whitespace, except in
  Markdown files.
- Run `npm run format` before committing changes to JS, CSS, HTML, or Markdown.

## Working with the blog

1. Add or edit a Markdown file in `blog/posts/`, with frontmatter fields
   `title`, `excerpt`, `author`, `date`, and optionally `tags`.
2. Run `npm run build:blog` to regenerate the HTML page and the RSS feed.
3. The generated page inherits a fixed header, footer, and nav from the
   template in `scripts/build-blog.js` — edit that template, not the
   generated HTML, if the blog layout needs to change.

## Deployment

`scripts/deploy.sh` does the full release: it runs `vite build`, runs the
blog build, copies `PrivacyPolicy/`, `email-templates/`, `CNAME`, and
`app-ads.txt` into `dist/`, then force-pushes the contents of `dist/` to the
`gh-pages` branch of the GitHub repo. GitHub Pages serves that branch at
`bridgitsocial.com`.

## Notes and gotchas

- `dist/` is a build artifact. Any manual edit there is lost on the next
  build. Change the source files instead: root-level HTML, `assets/css/`,
  or `blog/posts/`.
- Don't resurrect `archive/legacy-sass/` as a live build input without
  first reconciling it against `assets/css/main.css` — it's missing
  styling (CSS variables, the mobile nav) that only exists in the CSS
  today.
- `.env` is git-ignored. Copy `.env.example` to `.env` for local values.
  Most feature flags in `.env.example` are `false` — the web app, login, and
  blog comments are planned but not yet active.
- The site is pre-launch. Copy and CTAs point users toward the waitlist page,
  not a live app.
